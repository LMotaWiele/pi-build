## What changed

- `scripts/run-plan.mjs` — preserves model sessions across overflow continuations, appends continued-run logs, and gives the integration agent explicit test commands and a report requirement.

## Unfamiliar surface

Compared with your known list, these APIs and idioms are new:

- `fs.openSync` with `"a"` opens a file for appending, so continuation output joins the existing log instead of replacing it.
- `fs.existsSync` checks whether the session directory exists before scanning it.
- `fs.readdirSync` lists session files; filtering for `.jsonl` limits the scan to session logs.
- `String.trim` skips blank JSONL lines.
- `JSON.parse` decodes each session entry so the code can detect the custom continuation marker.
- `for...of` iterates directory entries and lines directly.
- The `try`/`catch` around `JSON.parse` skips malformed lines, including an unfinished final line.
- Object spread (`{ ...run, wallS }`) returns the run result with accumulated wall time.
- Default parameters (`append = false`, `continuing = false`) keep the new options optional.
- Conditional spread (`...(continuing ? [...] : [])`) adds `--continue` only for resumed invocations.
- `Array.filter` selects `.jsonl` files and excludes blank lines.
- `Array.join` formats the integration test commands and prompt text.
- The Pi CLI’s `--session-dir` and `--continue` options reuse a session; `-p` supplies the prompt for each invocation. The `"continue"` prompt asks the existing session to proceed after its continuation marker.
- `PI_BUILD_RETRY` is deleted from the inherited environment so this runner does not force a retry policy.
- `JSON.stringify` quotes test-command arguments when presenting them in the prompt.
- `§10` identifies the spec section the integration report must follow.

## The alternative

The simpler design is one Pi process per task with `--no-session`, restarting from the original prompt if work is interrupted. This version keeps a session directory and resumes only when the session records a continuation-needed marker. That preserves accumulated context and avoids rerunning from scratch; append-mode logging keeps the complete trace. The integration prompt now lists runnable test commands and requires a report, rather than leaving those details implicit.

## Verify by hand

- Confirm the Pi CLI’s `--continue` behavior selects the intended session when a directory contains multiple session files.
- Confirm the continuation marker is written before the process exits successfully; otherwise the runner will not retry.
- Confirm repeated retries append complete output and that the ten-attempt limit is appropriate for expected continuation chains.

## To modify this yourself

First understand how `runPi` launches Pi, how `runPiWithContinuation` detects markers and decides to resume, and how `piArgs` builds CLI arguments. Then inspect the session JSONL format and the integration prompt’s test-command construction before changing retry or reporting behavior.
