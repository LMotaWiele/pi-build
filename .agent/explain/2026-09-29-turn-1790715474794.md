## Unfamiliar surface

The code change in the touched source file uses familiar Node APIs and regular expressions; the test uses familiar Node test/assert APIs and a source-text check. The notable implementation idiom is recursive directory walking with `fs.readdirSync(..., { withFileTypes: true })`: directory-entry objects distinguish files from directories without an extra filesystem query. Here it lets validation check walkthrough files, including nested ones.

The walkthrough filename rule uses a regular expression to accept date-turn-ID Markdown names; `known.md` is explicitly exempted for compatibility. No unfamiliar library API appears in these touched code paths.

## The alternative

A dedicated explain-directory validation helper could make the filename rule easier to unit-test in isolation, and an AST-based check could inspect tool registration more semantically. This change keeps the checks small and local: the validator already has `walkFiles`, while the test deliberately reads source because the extension’s bundled `typebox` dependency is unavailable to the standalone Node test suite.
