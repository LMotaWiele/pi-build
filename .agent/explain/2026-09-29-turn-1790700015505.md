## 1. What changed

- `lib/plan.ts` — adds verification-check counting for table-based V-IDs and numbered legacy Verify lists.
- `scripts/pi-rework.ts` — uses shared spec discovery and resolution rather than duplicating filename parsing and matching.
- `scripts/run-plan.mjs` — delegates verification counting and test-command selection to shared modules, and runs recognized test commands.
- `bin/pi-implement` — adds a CLI pipeline to preflight a spec, create a review worktree, generate and validate a plan, run tasks, and record results.
- `docs/specs/SPEC-0010-run.md` — records implementation progress, checks, deviations, and remaining acceptance work.

## 2. Unfamiliar surface

No unfamiliar features or APIs beyond what’s already listed in `known.md`.

## 3. The alternative

The idiomatic alternative is to keep verification parsing, spec resolution, and test selection local to each script. Shared helpers won because the runner and CLI need consistent decisions, and one implementation is easier to test and maintain.

## 5. To modify this yourself

Understand the plan interface and validation in `lib/plan.ts`, then the shared spec and pipeline helpers. Trace `bin/pi-implement`’s preflight, worktree lifecycle, gates, and resume flow before changing orchestration. The live smoke and final-commit acceptance remain outstanding.
