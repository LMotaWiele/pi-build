## What changed

- `extensions/recap.ts` — session recaps now default to `.agent/recaps` instead of sharing the explain directory.
- `extensions/memory-gate.ts` — removes the `explain_write` tool and its prompt advertisement.
- `lib/markdown.ts` — removes `explainWriteName`, which generated sanitized filenames for that tool.
- `tests/markdown.test.ts` — adds a test that memory-gate neither registers nor advertises `explain_write`.

## Unfamiliar surface

No unfamiliar language features, standard-library calls, or library APIs are introduced. The test uses existing Node test and filesystem APIs to create temporary settings, capture registered tools and prompt handlers, then restore environment variables and clean up.

## The alternative

Recaps could keep using `.agent/explain`, or take their default directory from a shared constant. A separate `.agent/recaps` default keeps session summaries distinct from walkthroughs without adding another configuration dependency.

## Verify by hand

- The test checks the default tool names and prompt text, but not whether recap files are actually written under `.agent/recaps`.
- It doesn’t test a configured `recapDir` or whether that path is honored.
- The tool-registration assertion would catch `explain_write` returning, but the prompt assertion only checks the `pi_build_tools` section.

## To modify this yourself

First understand the split between session recaps in `extensions/recap.ts` and memory tools in `extensions/memory-gate.ts`. Then trace how settings blocks configure each extension and how `lib/telemetry.ts` controls recap output and test state.
