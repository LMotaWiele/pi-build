## What changed

- `lib/footer.ts` — Adds reusable formatting, usage aggregation, quota, and working-directory helpers.
- `extensions/quota-gate.ts` — Installs a dynamic TUI footer showing context, usage, quota, model, location, branch, session, and extension status.
- `tests/quota-footer.test.ts` — Tests token formatting, quota ordering, usage aggregation, and home-directory shortening.
- `README.md` — Documents the new visible quota and context information.

## Unfamiliar surface

- `path.relative`, `path.resolve`, `path.isAbsolute`, and `path.sep` — Normalize and compare paths safely when abbreviating the home directory.
- `Number.isFinite` and `Number.isInteger` — Validate numeric values and choose compact decimal formatting.
- Nullish coalescing (`??`) — Supplies defaults only for `null` or `undefined`, preserving valid zeroes.
- Optional chaining (`?.`) — Safely accesses optional extension context APIs.
- `Array.find` — Locates a quota window by label.
- `Map`, `Array.from`, and `localeCompare` — Sort and render extension status entries.
- `@earendil-works/pi-tui`’s `visibleWidth` and `truncateToWidth` — Measure and truncate styled terminal text without breaking layout.
- Pi’s `ui.setFooter` API — Registers a custom footer component with render, invalidation, and disposal lifecycle methods.
- `footerData.onBranchChange` — Requests a redraw when the Git branch changes.
- `requestRender` / `tui.requestRender` — Refreshes the footer after quota data changes.
- `Array<Record<string, unknown>>` with runtime shape checks — Reads heterogeneous session entries while remaining tolerant of Pi’s event formats.
- `toFixed` and regular-expression replacement — Produces compact, readable decimal percentages and token counts.

## The alternative

The footer could remain in the extension and perform all formatting inline, or it could show only percentages and omit detailed usage. The helpers were separated into `lib/footer.ts` so formatting and aggregation can be tested without constructing a TUI. Token counts were chosen over context percentages because they directly show remaining capacity relative to the model window; width measurement and truncation preserve both statistics and model identity on narrow terminals.

## Verify by hand

- Start the TUI at several terminal widths and confirm the footer truncates cleanly without overlap or broken styling.
- Switch branches, rename the session, and change models to verify the footer refreshes and displays the correct location, provider, and thinking mode.
- Trigger quota polling and response-header updates, confirming quota percentages visibly refresh without restarting the session.

## To modify this yourself

Understand Pi’s footer lifecycle (`setFooter`, render, invalidate, dispose), the shape of session entries and context-usage data, and the distinction between visible terminal width and raw string length. Then update the pure helpers and tests first, followed by the rendering and refresh wiring in `extensions/quota-gate.ts`.
