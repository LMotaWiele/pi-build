## What changed

- `lib/telemetry.ts` — raised the default per-turn prompt-token budget to 50 million and cost budget to $30.
- `settings/hosts/machina.json` — aligned Machina’s configured bounds with the new defaults.
- `settings/hosts/example.json` — aligned the example host configuration with the new defaults.
- `tests/bounds-split.test.ts` — uses the shared defaults when testing budget-triggered behavior.
- `tests/read-guard.test.ts` — uses the shared defaults when checking which budgets trigger a bound.

## Unfamiliar surface

No unfamiliar language features, standard-library calls, or library APIs appear in these changes. The tests now refer to `DEFAULT_BOUNDS`, an existing exported configuration object, rather than duplicating its numeric values.

known: DEFAULT_BOUNDS test expectations

## The alternative

The idiomatic alternative is to keep literal budget values in the tests. The tests instead use `DEFAULT_BOUNDS` so they stay aligned with the configured thresholds if those defaults change again.

## Verify by hand

- Confirm both host configuration files use the intended limits; tests exercise the shared defaults, not each host file’s parsed settings.
- Check any host-specific overrides outside these files: increasing defaults does not override a lower configured limit.
- Confirm the operational impact of permitting turns up to 50 million prompt tokens or $30 in cost is intentional.

## To modify this yourself

Understand how `DEFAULT_BOUNDS` in `lib/telemetry.ts` supplies fallback limits and how host `bounds` settings override them. Then update the shared defaults, host configurations, and tests together when changing the limits.
