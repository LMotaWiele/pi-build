## The alternative

The alternative was to keep fully qualified model IDs and resolve retry targets from the static routing map. The implemented approach uses separate provider/default fields and runtime tier transitions, so pi can validate the default consistently and retries can follow the actual current model and thinking level.

## Verify by hand

- Start a fresh session without `--model`; confirm it reports GPT-6 Sol at medium thinking.
- Trigger a written-file bound while on Luna; confirm exactly one retry switches to Sol, then verify Sol at high does not retry again.
- Temporarily remove or rename a configured model and run `./doctor.sh --offline`; confirm the diagnostic identifies the missing model.

## To modify this yourself

Understand the host JSON schema, pi’s composed `provider/id` model resolution, and the retry state machine in `lib/tiers.ts` plus `extensions/bounds.ts`. Then update the corresponding tests and run both doctor commands.
