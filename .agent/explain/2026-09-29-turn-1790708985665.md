## 1. What changed

- `docs/specs/SPEC-0010-run.md` — updates the run record with V14 smoke results, final acceptance checks, and handoff caveats.
- `scripts/run-plan.mjs` — excludes `.agent/` from files staged for plan commits so generated walkthroughs are not committed.
- `bin/pi-implement` — restores and cleans `.agent/` in the worktree before fast-forwarding the completed plan branch.

## 2. Unfamiliar surface

- `git add -A -- <pathspecs>` stages all changes while restricting which paths are included. Here, `:!.agent` excludes generated walkthroughs from commits.
- Git pathspec exclusion (`:!<path>`) negates a pathspec. It lets the runner stage the rest of the worktree without staging `.agent/`.
- `git restore --worktree -- <path>` discards worktree changes for the specified path; `git clean -fd -- <path>` removes untracked files and directories there. Together, they remove local `.agent/` changes that could block fast-forwarding.

## 3. The alternative

Instead of excluding `.agent/` at commit time and cleaning it before handoff, the runner could preserve those generated files in its commits or use a separate worktree for generated state. The chosen approach keeps walkthroughs local and out of implementation commits, while narrowly cleaning only `.agent/` to avoid interfering with other worktree changes.

## 4. Verify by hand

- Confirm the staging pathspec still includes intended implementation changes and excludes `.agent/` in both runner commit sites.
- Confirm the pre-fast-forward cleanup is limited to `.agent/` and that no needed user data lives there.
- The reported smoke and acceptance results are recorded in the run document; tests may not independently reproduce the external model calls, quota snapshots, or scratch-branch cleanup.

## 5. To modify this yourself

Understand the runner’s staging and commit flow in `scripts/run-plan.mjs`, then the branch handoff sequence in `bin/pi-implement`. Check how the project treats `.agent/` generated state before changing either path.
